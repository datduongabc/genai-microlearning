\clearpage\section{Progress and remaining work}\label{sec:plan}\label{sec:progress}
\subsection{Status on 7 November 2026}
Phase 2 began on 26 October 2026 with a twelve-week baseline ending on 17 January 2027 and a target defense on 18 January 2027. After two weeks, the system described in the midterm report has been implemented and extended with the scalable architecture of Section~\ref{sec:architecture}. The automated test suites pass: 1,553 backend tests on Python 3.14 and 273 frontend tests, checked by continuous integration on every change. The evaluation of generated content, which depends on paid models and human raters, has not started. A first \code{terraform apply} on a real AWS account on 6 November created the network, database, cache, load balancer and storage, 110 resources, and stopped at CloudFront, which AWS refuses to a new account until it has verified it; the stack was destroyed the same day. That run also exposed two faults in the deployment script, a first deployment that is not restarted after the migration and a fixed final snapshot name; both are fixed. Since then, failure tests on one machine (Section~\ref{sec:results-failure}) found and fixed a chat error and shortened recovery from a crashed worker, and students can now enter through LTI to chat with their course's material (Section~\ref{sec:lti-learners}). A walk-through of both roles in a real browser found that a lecturer was shown a provider's exception text for a document the system had failed; the lecturer is now told to retry later.

The advisor's feedback after the midterm set the targets this work is judged against: the five-subject corpus, retrieval metrics (Hit Rate@$K$, MRR, nDCG), faithfulness and answer relevance, latency and resource profile, agreement between raters and between human and model judges, a strategy for figures and code in documents, a cloud-native AWS deployment within \$200 with a justified budget and lock-in, and integration with Moodle through the LTI tool model. \subsection{Budget}
The AWS estimate uses published Singapore on-demand prices from November 2026. Planned use is about 75 hours of demonstration and 10 hours of load tests: Fargate \$86.11, CloudWatch \$10.84, RDS \$15.51, EC2 for Moodle and the load generator \$5.92, load balancer and public addresses \$10.03, and Valkey, S3 and ECR \$3.82, a total of \$132.24, or about \$159 with a 20\% margin. Removing the NAT gateway and, if Jev is approved, the reranker task lowers this; the estimate has not been recomputed for those changes. The environment is destroyed after each session, and budget alarms fire at \$50, \$100 and \$150. Running continuously would cost about \$784 per month, well beyond the credit.

Model use is not covered by the AWS credit. A module costs about \$0.056 with Claude Haiku 5.5, from a secondary price source. Jev costs about \$0.0007 per retrieval from TypeSafe's published price, about \$0.005 per module, and breaks even with a self-hosted reranker task at about 350 retrievals per hour.

\subsection{Conclusion}
The authoring system is implemented end to end, from upload through generation and editing to Moodle publication and LTI entry, and it runs as stateless services that can be deployed to AWS from code. The measurements so far identified the bottlenecks (CPU reranking, provider rate limits and a thread-pool stall) and showed each one removed on one machine. What the thesis still has to show is the quality of the generated modules and the system's behaviour on AWS. Both are planned and ready to run; both wait on credit, and the quality study also waits on raters.
